About

I’m Yuchen. I study electrical engineering and I write up what I measure.

I’m in the M.S.E. programme in Electrical Engineering at the University of Pennsylvania (2026–2028). Before that I did an honours dual degree in Computing and Commerce at Queen’s University (2022–2026), and in summer 2025 I was a big-data engineering intern on a logistics forecasting platform at Shopee, consolidating SQL jobs into a PySpark and Hive batch layer.

The work on this site sits between models and the machines that run them: how requests should be routed across GPUs, what happens to a small model when it is quantized to fit a laptop, how fast bytes can be chunked. This semester I am adding the other side: firmware on an ATmega328PB, SoC architecture on an Ultra96, and circuits in a VLSI course.

How I approach a project

  1. Start from a decision. The text-to-SQL project asks whether a small model should ship as an autonomous answerer, and the answer is written as a decision, not as a score. {% for n in notes if n.slug == "wrong-answers-that-raise-no-error" %}See the note.{% endfor %}
  2. Write down the acceptance criteria, and say where they came from. Mine were assumptions, and the README says so.
  3. Report the condition with the number. “611 ms p95” means an Apple M1, one request at a time; with four in parallel it is 1.4 s.
  4. Say what would change the conclusion. Every repository ends with its limits, and the routing result turned on the size of a cache. {% for n in notes if n.slug == "simulation-cannot-see-a-cache" %}See the note.{% endfor %}
